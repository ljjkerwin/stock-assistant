# 暗盘资金模块（DarkTrade）

> 本文档是 [AGENTS.md](../../AGENTS.md) 的卫星文档。改动暗盘抓取、索引或字段映射时**同步更新本文件**。接口行见 [docs/api.md 暗盘资金](../api.md#暗盘资金)。

## 工作机制

- **定时自动重建**：每天北京时间 **09:28（仅限开盘交易日，周一至周五）**，系统中央心跳服务会自动触发全量索引重建，确保在开盘（09:30）前索引已就绪。
- K线总览页在加载时会自动携带客户端今日日期调用 `GET /api/darktrade/snapshots-batch?codes=&date=YYYYMMDD`，后端检测到索引日期不匹配时自动作为兜底在服务端并发锁中触发全量索引刷新（爬取约 177 页 ~5300 只股票，约 5–10 秒），**无需手动运行脚本**
- 手动刷新仍可用 `node scripts/refresh-darktrade-index.mjs [YYYYMMDD]`（调用 `POST /api/darktrade/refresh-index`）；管理页的「获取并写入数据库」复用同一流程，索引建立后只写入一次全市场快照，避免重复批量 upsert
- `refresh-index` 建立 `code → (page, index)` 映射；`snapshots-batch` / `:code` 通过该映射定位再取数；`date` 不匹配时，`snapshots-batch` 接口同样会在服务端用并发锁触发一次刷新（多请求只刷新一次）
- **静态排序防飘移**：建立索引和抓数时统一默认采用静态的股票名称排序（`sortFlag=4`）。因为股票名称的 Unicode 顺序是绝对静态不变的，这规避了按暗盘资金等动态指标排序（`sortFlag=6`）时，因股票排名盘中剧烈变化而导致其漂移到其他页面，进而导致接口请求错失并回退至静态旧数据（使明暗盘数据看似卡死、不更新）的 Bug。
- **明暗盘挖掘**：分钟快照写入时会同步 upsert `dark_trade_daily_result`（唯一键 `(trade_date, code)`），维护每只股票当日最新的 `captureMinute` 与资金、行情展示字段。`GET /api/darktrade/discovery?minDarkCapital=&minMultiple=&date=` 直接查询该每日结果表，不扫描或聚合分钟快照表；`(trade_date, dark_capital)` 索引支持日期筛选与暗盘资金排序。全市场刷新在相同 `(code, captureMinute)` 上以最新数据覆盖，且不区分全市场与收藏标的的局部分钟快照。历史日期结果表为空时，接口会从既有快照按最新时间一次性回填，后续查询保持轻量。再按传入的最低暗盘资金和相对明盘资金绝对值的倍数筛选（均严格大于）。两个资金参数省略时默认 2,000 万元和 2 倍，并按暗盘资金降序返回；前端以“万”为单位编辑最低暗盘资金，并在请求前换算为元；日期也是筛选条件，默认当天。
- **管理中心收盘暗盘资金查询**：`GET /api/darktrade/daily-result?name=&date=` 按日期和股票名称从同一每日结果表查询一只股票的 **15:00 收盘**资金，支持完整/部分中文、拼音首字母和混合输入（如 `华电ln`、`zjxc`）；多候选时依次优先完整名称、中文名称前缀（如 `康德` 优先“康德莱”而非“药明康德”）、完整拼音首字母（如 `dfd` 优先“多氟多”而非仅匹配前三字的“东方电子”）和其他部分匹配。没有归档数据时返回 `null`，不会额外请求上游。若命中股票当天只有盘中实时资金、尚无 `1500` 快照，则返回错误，不展示盘中值。结果名称随机保留前 1 或 2 个汉字，其余汉字用拼音首字母表示，例如 `华电ln` 或 `华dln`；金额低于 1,000 万使用 `w`（万），达到 1,000 万使用 `y`（亿），`y` 最多保留两位小数；正数会显示 `+`，例如 `华电ln，暗+0.23y，明-2.1y`、`同花s，暗+2.67y，明+2.2y`。
- **管理中心 LLM 查询**：`POST /api/darktrade/daily-result-from-text` 接收一句话和可选日期。文本来源为小红书股票咨询回复，模型专门保留其中的隐晦股名写法（中文、拼音首字母或混合形式，如 `多F多`、`北方华c`、`dfd`），去除“求看”“谢谢”等语气词而不擅自还原为正式全称。后端固定调用硅基流动 OpenAI 兼容接口 `https://api.siliconflow.cn/v1/chat/completions` 与模型 `Qwen/Qwen3.5-4B`（关闭思考模式），使用 `SILICONFLOW_API_KEY` 鉴权；仅提取最多 12 个文本中可能提及的股票或场内 ETF 名称，随后逐一复用上述日终查询，并返回命中的 `results` 和未命中的 `notFoundNames`。模型密钥始终只保留在后端环境变量中。
- **自愈重构索引**：即便采用名称排序，若盘中发生交易的股票总数增加（新股票获得交易被计入），股票的相对页码仍可能发生微调（例如 300059 东方财富在 09:30 位于第 150 页，盘中随前序字母股票增多而漂移到第 153 页）。为此，服务层实现了自愈机制：在获取最新数据时，若发现已索引的标的未在其对应页码中找到，且距离上次刷新已超过 5 分钟，将自动触发索引重构并二次拉取，确保分时数据能够实时更新。

## 暗盘快照（分时副图）

- 后端按交易时段定时抓取快照写入 `dark_trade_snapshots`（开盘前 09:30 之前的快照过滤不写入/不返回），形成**当日分钟粒度**的暗盘/明盘资金累计序列
- **收盘/午休与即时补点**：
  - 09:30–15:00 期间按抓取时的实际分钟打 `captureMinute`；
  - **收盘后**（北京时间 ≥15:00）再次拉取时，源数据已是当日收盘终值，会补写为 `${date}1500` 的 15:00 收盘快照，填上 242 槽位横轴最后一槽；
  - **中午休息时间**（北京时间 `11:31`–`13:00`）拉取/抓取的数据，统一将 `captureMinute` 映射为 `${date}1130`，算作是 11:30 的收尾数据点，保证能在此时间槽渲染出数据而不会因盘外时间点被前端过滤；
  - **即时按需刷新**：在获取今日快照 `snapshots-batch` 时，若查询的是今日，后端会即时调用一次 `getBatchDarkTrade` 以触发针对这些股票代码的最新暗盘数据抓取并写入当前快照，避免新打开的股票（非收藏标的）因没有定时轮询而无图表数据的尴尬。
- **股票详情页分时图**与 **K 线总览页**的暗盘均通过 `GET /api/darktrade/snapshots-batch?codes=&date=YYYYMMDD` 按**当日交易日**拉取分钟粒度快照。为了节省网络请求开销，K 线总览页去掉了对 `/api/darktrade/batch` 的依赖，卡片右上角的明暗盘最新汇总值也是直接从该快照列表的最后一根中提取数据进行渲染。其中详情页的交易日由 `KLineChart` 加载 K 线后经 `onDateResolved` 上报「K 线实际交易日」（而非客户端日历日，规避周末/盘前不一致），父组件据此调 snapshots-batch 取 `Record[code]`
- 前端 `KLineChart` 与总览页暗盘副图：明盘蓝线 + 暗盘黄线 + 总中灰折线，横轴用 241 槽位（09:30–11:30 + 13:01–15:00，午休不画）与分时主图逐槽对齐，无快照的分钟留空
- `GET /api/darktrade/snapshots/:code?days=` 为**日粒度**历史快照（每日取最后一条，默认 60 天）：历史交易日只返回 15:00 收盘快照；当日北京时间未收盘时，返回最新盘中快照作为当日临时值。个股详情页的日K线通过该接口获取历史明暗盘资金数据并渲染在副图中（查询 1000 天数据）。

## 数据源与编码

- 数据源：东方财富 `quotederivates.eastmoney.com/datacenter/darktrade`，支持 `date=YYYYMMDD` 参数
- 返回 **GBK 编码**，服务层用 `TextDecoder('gbk')` 解码，**无需额外安装 iconv-lite**

## 字段映射

| 键     | 含义                                   |
| ------ | -------------------------------------- |
| `"6"`  | 暗盘资金（元）                         |
| `"7"`  | 明盘资金（元）                         |
| `"8"`  | 主力净流入含暗盘（元）                 |
| `"11"` | 暗盘活跃度（小数）                     |
| `"13"` | 最新价 × 1000                          |
| `"14"` | 涨幅（小数，如 `0.0188` 表示 `1.88%`） |
| `"16"` | 名称                                   |
| `"17"` | 行业                                   |
| `"18"` | 概念                                   |
